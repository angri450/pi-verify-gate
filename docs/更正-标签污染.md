# 更正：返工标签被污染，验证/返工关联不成立

## 原来声称的

| 情况 | n | 后来被返工 |
|:--|--:|--:|
| 宣称修好 + 这轮有工具报错 | 105 | 36.2% |
| 宣称修好 + 没跑测试 | 146 | 32.9% |
| 宣称修好 + 跑过测试 | 26 | 3.8% |
| 不宣称（普通收尾） | 1,547 | 20.4% |

命中条件 `宣称 && (没测试 || 报错)`：n=167，返工 29.3%，未命中 20.4%，Fisher p=0.0093。

## 两个杂音

**一、标签把文档算成返工。** "文件后来又被改一次"对文档不成立——README 跟着任务反复更新是常态。实测：

| 主改类型 | n | "返工"率 |
|:--|--:|--:|
| 文档（.md/.txt/.rst） | 491 | 47.0% |
| 代码 | 441 | 41.7% |
| 配置 | 12 | 25.0% |

文档比代码还高，说明这个标签量的是"还会不会再碰这个文件"，不是"做没做对"。

把标签改成"只算代码文件被再改"（n=547）：没跑测试 26.3%（n=312）vs 跑了测试 31.1%（n=235），**方向反了，Fisher p=0.25**。

**二、旧基线混进了没改文件的轮次。** 没改任何文件的轮次在该标签上必然是 0（没文件可被再改），把基线人为压低。把基线限制在有改动的轮次里（n=959，基线 43.8%）：

| 组 | n | 返工率 |
|:--|--:|--:|
| 宣称修好 | 119 | 46.2% |
| 不宣称 | 840 | 43.5% |
| 宣称 + 没测试 | 91 | 57.1% |
| 宣称 + 跑了测试 | 28 | 10.7% |
| 不宣称 + 跑了测试 | 235 | 34.0% |
| 不宣称 + 没测试 | 605 | 47.1% |

最后两行看着支持"跑测试有用"，但跑测试的轮次绝大多数是**代码轮次**，不跑测试的绝大多数是**文档轮次**——"跑测试"一直在替"代码/文档"背锅。控制住主语，效果归零。

## 修正后的结论

- 验证与返工的关联：**不成立**
- 模型自评的完成声明与真相：**无关**（p=0.62）
- 文档比代码更常被再碰（47.0% vs 41.7%）：**是陷阱警告**，不是发现——在 pi 这类会话里，任何拿"文件被再改"当结果标签的指标都不干净

## 什么东西还站着

- 模型在最终回答里把不确定抹掉了：思考 18.5 个犹豫词/万字符，回答 4.0；含犹豫词的消息比例 51.5% vs 4.8%
- 位置/阶段信号：段级预测"接下来会不会自我纠正"，只看位置 AUC 0.5616，词特征 0.6019，加块内累计上下文 0.6357；系数上位置碾压（pos -0.91、sqrt_pos +0.73），犹豫词全在 0.03 以下
- MRF 局部平滑：不成立（相邻相关只比随机高 0.03）

## 教训

"返工"是唯一零成本的结果标签，但它同时被三件事污染：文档本来就反复改、大功能本来就要多轮迭代、同一文件多次小修也是常态。真正需要的是**外生标签**（任务最终有没有被用户接受、测试最终有没有通过、人工标注一小批）。没有外生标签，会话内部挖出来的任何相关性都可能是主语或阶段在背后操纵。
